# ТЗ: исправления по результатам ручного QA (склад, приёмка, пост)

**Основание:** ручное тестирование (Android), воспроизводимость подтверждена по текущему коду репозитория.  
**Стек:** Next.js (App Router), React, shadcn/ui, `ReceiveModal` / `CreateItemForm`, `Inventory`, `EditItemModal`, `EditBrandModal`, `StockMovementsPanel`, `ScanModal`, `PostGenerator`.

**Приоритеты:** P0 — блокирует работу / вводит в заблуждение; P1 — сильный UX; P2 — полировка.

---

## 0. Общие требования (сквозные)

| ID | Задача | Приёмка |
|----|--------|---------|
| G-01 | **Онбординг по экранам** | У заголовков ключевых экранов (минимум: Склад, Продажа, Пост в чат, Долги, Отчёты) — контрол «?» или аналог: краткий текст + ссылки на сценарии. Контент хранить в одном месте (константы / MDX / i18n — на усмотрение исполнителя). |
| G-02 | **Единообразие контролов** | Выбор категории/бренда везде через один визуальный паттерн (как в `CreateItemForm`: `Select` + `SelectTrigger`), не «сырой» `<select>`, если в остальном приложении принят shadcn `Select`. |
| G-03 | **Числовые поля** | Единое поведение пустого значения и нуля: либо контролируемая строка с `inputMode="decimal"`, либо `type="number"` везде одинаково; не смешивать «пусто → 0 как текст» и «пусто → пустая строка» в соседних полях одной формы. |

Закрытие — только по явной кнопке «Готово» / крестик. | Можно принять ≥2 позиции подряд без повторного открытия модалки с главной/склада. |
| R-02 | P1 | Тост «Товары приняты…» `duration: 5000` мешает сразу начать следующее действие | Тост после `onOpenChange(false)` | Тост не блокирует взаимодействие: `pointer-events: none` на контейнере тоста **или** сократить длительность **или** stacking / dismiss по тапу вне; проверить `sonner`/toast-обёртку. | На Android можно тапнуть «Приём товара» / поле поиска, пока тост виден. |
| R-03 | P0 | Пустой список брендов: «Выберите бренд» + пустое меню («бургер») | `CreateItemForm`: `Select` бренда при `brands.filter(...).length === 0` (~стр. 1331–1358) | Если список пуст: не открывать пустой `SelectContent`; показывать текст «В этой категории ещё нет брендов — создайте новый» и кнопку переключения на «Создать новый». | Пустого выпадающего списка нет; пользователь понимает следующий шаг. |
| R-04 | P1 | Автофокус в поле штрихкода при открытии «Новый товар» неудобен (прыгает layout, не все начинают со штрихкода) | `useEffect` с `barcodeInputRef.current?.focus()` (~стр. 1814–1820) | Убрать автофокус **или** фокус только если передан `initialBarcode` / пользователь открыл сценарий сканирования; первый фокус — «Категория», если штрихкод необязателен. | Открытие формы без всплытия клавиатуры до явного тапа (Android). |
| R-05 | P1 | Плейсхолдер штрихкода не помещается | `placeholder="Оставьте пустым, если нет штрихкода"` (~стр. 1208) | Короткий плейсхолдер + `title`/подсказка под полем / иконка «?». | Текст подсказки читается целиком на ширине 320px. |
| R-06 | P1 | Крепость: допускаются буквы; ожидаются только цифры | Поля «Крепость (мг)» `Input` без ограничения (~стр. 1459–1478) | Ввод: только цифры (и опционально одна точка для дроби, если нужно); суффикс `mg` подставлять при сохранении, как в `handleSubmit` нормализации (~стр. 1174–1185). Согласовать с **B-02**. | Невозможно ввести «abc»; в БД уходит нормализованное значение. |
